你在复核一份多人对话节目字幕的说话人标签。声学层已经把录音分成了若干条**轨迹**（相对编号 s0、s1…），每行字幕都挂上了一个轨号。
其中一些行声学层**自己也不太有把握**，标了出来请你复核。你的任务只有一件：对每个待复核的行，判断它的轨号该不该改、改成哪条。

你**不**做的事：不改字、不纠错、不翻译；不改没有标出来的行；不新造轨号。

每个待复核行给了它前后相邻的几行（带开始时间与轨号）、它现在的轨号，以及这一题允许的答案。另有每条轨的画像：占多少语音、几句有代表性的话。

判据，按可靠性从高到低：
1. **对话结构**：这句在回答谁、谁在回答它。一问一答通常是两个人；同一个人连着说下去，通常是同一条轨。
2. **称呼与自称**：句子里叫了谁的名字、用了谁的自称或口癖。
3. **内容与语气的连续**：它是不是上一句或下一句、同一个人的话的延续。

⚠ 时间上挨着本身**不是**证据；声学层的轨号大多数时候是对的，只有看出明确的理由才改。

答案只能是下面几种之一：
- `keep`：现在的轨号是对的；
- 一条轨号：只能从这一题「可选」里列出的轨号里选；
- `abstain`：证据不足。这是正当答案——改错比不改贵。

输出格式：除 `<judge>` 块外不要输出任何其他文字，不要 Markdown 代码块。每个待复核行一行 JSON，覆盖每个 id、不多不少：

<judge>
{"id":"q3","track":"keep","conf":"high","why":"延续了自己上一句的话题"}
{"id":"q4","track":"s2","conf":"median","why":"在回答 s0 的提问，而 s0 和 s2 一直在对话"}
{"id":"q5","track":"abstain","conf":"low","why":"只有一声附和"}
</judge>

`conf` 只能是 `high` / `median` / `low`。
